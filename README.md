# Credit Card Fraud Detection Using Logistic Regression

## Project Overview
This project uses machine learning to classify financial transactions as **fraudulent** or **legitimate**. It explores transaction data, addresses class imbalance, trains a Logistic Regression classifier, and evaluates performance using metrics suited to fraud detection.

## Dataset
The notebook uses a **synthetic dataset of 10,000 transactions**. Features include:
- Transaction amount
- Transaction hour
- Merchant category
- Foreign transaction indicator
- Location mismatch indicator
- Device trust score
- Transaction velocity in the last 24 hours
- Cardholder age

The target column is `is_fraud` (`0` = legitimate, `1` = fraud). The notebook reports a class distribution of approximately 98.49% legitimate and 1.51% fraudulent transactions.

> **Dataset note:** The notebook currently reads `/content/credit_card_fraud_10k.csv`, which is a Google Colab path. Add the CSV to your repository (if you are permitted to share it) and update the notebook path, or provide instructions for obtaining the dataset. Do not upload sensitive or restricted data.

## Workflow
1. Load and inspect the dataset.
2. Perform exploratory data analysis (EDA), including checks for missing values, duplicates, distributions, and class imbalance.
3. Remove `transaction_id` and separate the features from the target.
4. Split the data into training and test sets using an 80:20 stratified split.
5. One-hot encode `merchant_category`.
6. Standardize numeric features using `StandardScaler`.
7. Apply SMOTE to the training data to address class imbalance.
8. Train a Logistic Regression classifier.
9. Compare classification thresholds and evaluate the model with a confusion matrix, precision, recall, F1-score, ROC-AUC, and Average Precision.
10. Save the trained model and scaler with Joblib and demonstrate a prediction for a new transaction.

## Reported Results
The notebook reports the following results at a decision threshold of **0.9**:

| Metric | Score |
|---|---:|
| Accuracy | 98.25% |
| Precision | 45.61% |
| Recall | 86.67% |
| F1-score | 59.77% |
| ROC-AUC | 99.33% |
| Average Precision | 75.10% |

Fraud detection is an imbalanced classification problem, so accuracy alone is not enough. Recall indicates how many actual fraudulent transactions were detected, while precision reflects how many transactions flagged as fraud were actually fraudulent.

*These are the results recorded in the notebook; they have not been independently reproduced here.*

## Limitations
- The dataset is synthetic, so results may not generalize to real banking transactions.
- The reported metrics depend on the selected threshold and test split.
- A high ROC-AUC does not by itself guarantee useful operational performance; precision, recall, and the cost of false positives/false negatives also matter.
- This notebook is a learning project, not a production fraud prevention system.
